# 部署到自己的服务器

选择 Docker Compose 或宝塔 Node 项目，两种方式使用同一源码和数据库模型。GitHub 仓库托管代码，不会自动提供 Node / MySQL / Redis 服务；不能把该应用直接发布为纯静态 GitHub Pages。

## 方案 A：Docker Compose

### 首次安装

要求 Linux 服务器、Docker Engine、Compose v2，以及首次生成配置所需的 Node.js 24 / pnpm 11.25.0。预留数据库、构建与图片存储空间。

```bash
git clone https://github.com/Senyroom/senyu-design-studio.git
cd senyu-design-studio
corepack enable
corepack prepare pnpm@11.25.0 --activate
pnpm install --frozen-lockfile
pnpm setup:production
```

在服务器安全编辑 `.local/production.env`，不要提交到 Git：

- `SITE_URL` 首次本地检查用 `http://localhost:8080`；正式访问改为真实 `https://你的域名`。
- HTTP 检查阶段 `COOKIE_SECURE=false`，正式 HTTPS 时为 true。
- 保留随机数据库密码、初始管理员密码和发布密钥；不要使用 `.env.example` 中的占位值。

```bash
docker compose --env-file .local/production.env config --quiet
docker compose --env-file .local/production.env build
docker compose --env-file .local/production.env up -d --wait mysql redis
docker compose --env-file .local/production.env run --rm init
docker compose --env-file .local/production.env up -d api web gateway
docker compose --env-file .local/production.env ps
```

本机访问 `http://localhost:8080` 与 `/admin/`。远程服务器可使用 SSH 本地转发检查；不要为检查把数据库端口暴露到公网。

### 域名与 HTTPS

将域名指向服务器，由主机 Nginx 或 Caddy 安装证书，并将流量代理到 `127.0.0.1:8080`。可参考 `deploy/Caddyfile.example`。设置真实 SITE_URL 和 COOKIE_SECURE 后重建应用环境：

```bash
docker compose --env-file .local/production.env up -d --force-recreate api web
```

反代应保留 Host / X-Forwarded-Proto，支持至少 13 MB 请求。Compose 网关已将 `/admin/`、`/api/v1/`、`/media/` 和前台路由组合到同一个域名，拒绝外部 `/api/revalidate`。

### 更新

先备份数据库和媒体；保留生产配置，不导入开发数据库。构建后在停写窗口运行 additive migration，再启动：

```bash
git pull --ff-only
docker compose --env-file .local/production.env build
docker compose --env-file .local/production.env stop gateway web api
docker compose --env-file .local/production.env run --rm --no-deps api pnpm db:migrate
docker compose --env-file .local/production.env up -d api web gateway
```

通常不需要再次 seed。前台内容编辑通过后台发布即可，不必重新构建。

### 备份与恢复

```bash
bash scripts/backup.sh .local/production.env /安全目录/senyu-backups
```

备份期间会短暂停止网关和应用以确保 SQL 与媒体一致，输出压缩文件与 SHA256 校验。环境密钥须另外安全保存。备份目录必须在项目与媒体目录外，并限制访问。

可在独立的全新 `recovery-*` Compose 项目恢复：

```bash
bash scripts/restore-rehearsal.sh .local/production.env /安全目录/senyu-backups/时间目录 recovery-check-20261107
```

恢复脚本不覆盖正式 volume，不自动切换流量。需要浏览器验收时为恢复实例配置不同网关端口，避免 8080 冲突。Redis 不需要恢复，MySQL 公共版本行随 SQL 一起恢复。

## 方案 B：宝塔 Node 项目

### 准备与构建

在宝塔安装 Nginx、Node.js 24、MySQL 8 和 Redis。只允许网关的 HTTP(S) 对外访问，数据库与缓存使用回环地址。下面用 `/www/wwwroot/example.com/app` 举例，不是现有生产服务器配置。

1. 将仓库放入该 app 目录，创建独立 MySQL 数据库和用户。
2. 复制 `.env.example` 为 app 根目录 `.env`，配置随机密钥与真实数据库连接。
3. 媒体放在 app 外部，例如 `/www/wwwroot/example.com/media`，设置 `MEDIA_ROOT` 并允许运行用户读写。
4. API 端口设为 4100，`HOST=127.0.0.1`；前台 `WEB_PORT=3100`。
5. `API_INTERNAL_URL=http://127.0.0.1:4100`，`WEB_INTERNAL_URL=http://127.0.0.1:3100`。
6. `WEB_ORIGIN`、`ADMIN_ORIGIN`、`NEXT_PUBLIC_SITE_URL` 均设为真实 HTTPS 域名，`COOKIE_SECURE=true`。

```bash
pnpm install --frozen-lockfile
pnpm db:generate
pnpm db:migrate
pnpm db:seed   # 仅首次空库初始化
pnpm build
```

### 创建两个 Node 项目

| 配置 | 前台 | API |
| --- | --- | --- |
| 项目名称示例 | senyu-web | senyu-api |
| 运行目录 | app/apps/web | app/apps/api |
| 启动命令 | node /www/wwwroot/example.com/app/scripts/start-web.mjs | node /www/wwwroot/example.com/app/apps/api/dist/main.js |
| 端口 | 3100 | 4100 |
| 用户 | 具有应用 / 媒体权限的受限用户 | 同左 |
| 域名 | 绑定真实域名并开启外网映射 | 不绑定独立域名，不公开端口 |

使用宝塔「网站 → Node 项目」管理进程，不把这个项目放入 HTML 项目，也不要同时运行另一套 systemd 服务占用端口。

### 配置 Nginx 路由

前台 Node 站点安装证书并强制 HTTPS。把后台构建 `app/apps/admin/dist` 以目录或软链接放入专门的静态根目录 `public/admin`，不要将 app 根目录当作可下载静态目录。示例 location 片段见 [deploy/baota-locations.conf.example](../deploy/baota-locations.conf.example)，加入 Node 站点对应的服务块时替换路径。

宝塔生成的前台 `location /` 代理到 3100，其他路径按片段配置。API 与 Next 的内部刷新使用回环地址，不公开刷新接口或 Swagger。

### 更新、备份与检查

- 更新前先在 Node 面板停止 API，备份完整 MySQL SQL、整个媒体目录和配置，再启动 API。
- 新版本先在隔离副本安装、迁移和构建，验证后切换；保留旧构建供回退。
- 通过面板重启两个 Node 项目，不用 systemctl 启动同名旧服务。
- 确认首页、后台、媒体和 `/api/v1/health` 正常，Redis connected 为 true。
- 后台保存草稿、预览、发布，核对前台内容；确认 `/api/revalidate`、`/api/docs` 和 `/.env` 不可公开访问。
- 已上线后不能用开发快照覆盖生产数据；破坏性 schema 变更需要单独迁移和回退计划。

备份必须同时包含 SQL 与媒体；不要在 MySQL 写入时直接拷贝数据库数据目录。恢复时先导入独立数据库与媒体目录，验证后切换配置，避免覆盖当前线上内容。
