# 从零安装森语设计所

本文面向第一次部署该项目的使用者。先在本地完成安装和后台编辑，再部署到自己的服务器。默认图片和文章都可以替换。

## 1. 准备环境

- Git。
- Node.js 24 与 pnpm 11.25.0（版本以根目录 `packageManager` 为准）。
- Docker Engine + Compose v2；Windows 使用 Docker Desktop 的 Linux 容器模式。
- 安装依赖和首次拉取镜像时需要访问 npm 和镜像仓库。

```bash
node --version
corepack enable
corepack prepare pnpm@11.25.0 --activate
pnpm --version
docker compose version
```

如果没有 Corepack，可通过自己的 Node 版本管理器启用，或安装 `pnpm@11.25.0`。首次部署不要随意更新 Next.js、Prisma 或锁文件。

## 2. 下载源码并安装依赖

```bash
git clone https://github.com/Senyroom/senyu-design-studio.git
cd senyu-design-studio
pnpm install --frozen-lockfile
```

## 3. 生成独立开发配置

```bash
pnpm setup:dev
```

脚本生成 `.env` 和 `.local/登录信息.md`，包含随机数据库密码、管理员密码与发布密钥；不会覆盖现有 `.env`。本地媒体保存在 `.local/media`，都已配置 Git 忽略。

开发配置默认使用 MySQL 端口 13306、Redis 端口 16379，且只监听回环地址。应用默认前台 3000、API 4000、后台 5173。

## 4. 启动 MySQL 8 和 Redis

```bash
docker compose -f compose.dev.yaml up -d --wait
docker compose -f compose.dev.yaml ps
```

首次需下载镜像并初始化数据库，等待服务健康。`compose.dev.yaml` 只启动数据库和缓存，不是完整生产部署。

如果使用已有 MySQL / Redis，跳过此步，复制 `.env.example` 并填写实际配置。手动在 MySQL 建立独立的 `personal_site` 数据库和用户，字符集用 `utf8mb4`。将 `DATABASE_URL` 改为该用户的连接串，密码中的特殊符号需 URL 编码。不要连接到正式数据库练习。

## 5. 初始化表和演示内容

```bash
pnpm db:generate
pnpm db:migrate
pnpm db:seed
```

初始化包含站长账号、3 个文章分类、9 篇站内演示文章、站点资料与本地媒体。默认图片已经包含在仓库，不需要访问参考站下载。`db:seed` 对已有记录使用非覆盖初始化；它不是生产数据迁移工具。

## 6. 启动应用

```bash
pnpm dev
```

- 前台：http://localhost:3000/
- 后台：http://localhost:5173/admin/
- API：http://127.0.0.1:4000/api/v1/health

在 `.local/登录信息.md` 中查看初始账号和随机密码。登录后依次设置个人资料、导航、模块、文章、课程与联系方式，再保存、预览和发布。

API 的开发命令先编译再用 Node watch 观察输出；修改 API TypeScript 后需要重新运行 `pnpm --dir apps/api build` 或重启开发命令。前台与后台由 Next / Vite 提供热更新。

## 7. 关键配置解释

| 变量 | 用途 |
| --- | --- |
| `DATABASE_URL` | 独立 MySQL 8 连接串 |
| `REDIS_URL` | Redis 连接串；不配置时回源 MySQL |
| `REDIS_KEY_PREFIX` | 不同环境使用不同 key 前缀 |
| `MEDIA_ROOT` | 服务器本地媒体目录，包含 private 和 public |
| `PORT` / `HOST` | API 端口与监听地址 |
| `API_INTERNAL_URL` | 前台和开发后台代理访问 API 的内部地址 |
| `WEB_ORIGIN` / `ADMIN_ORIGIN` | 浏览器实际访问来源，协议、域名、端口必须对应 |
| `WEB_INTERNAL_URL` | 发布任务访问前台刷新接口的内部地址 |
| `NEXT_PUBLIC_SITE_URL` | 站点地图、SEO 的对外域名 |
| `REVALIDATE_SECRET` | API 与前台刷新接口共享的随机密钥 |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | 仅用于首次初始化管理员 |
| `COOKIE_SECURE` | 本地 HTTP 为 false，正式 HTTPS 为 true |

不要把 `localhost` 和 `127.0.0.1` 随意混用于后台访问，Origin 必须与配置一致。后台修改密码不会改写 `.env` 或初始登录文件。

## 8. 检查安装结果

```bash
pnpm typecheck
pnpm build
# 另开终端保持 API 和前台运行，使用独立开发数据库
pnpm test
```

测试会短暂修改公开测试内容，然后清理本轮 QA 数据并恢复站点资料，只能用于开发 / CI。不能对线上数据库运行。

## 9. 停止和再次启动

前台开发终端按 Ctrl+C。停止开发数据库：

```bash
docker compose -f compose.dev.yaml stop
```

下次启动同一项目：

```bash
docker compose -f compose.dev.yaml up -d --wait
pnpm dev
```

不要删除数据库 volume 来解决登录或迁移问题，里面可能已经有你编辑的内容。

## 常见问题

### Docker 无法连接

确认 Docker Desktop 已启动，且使用 Linux 容器模式。`docker info` 成功后再运行 Compose。

### 数据库或 Redis 端口被占用

首次初始化前可设置 `DEV_MYSQL_PORT` / `DEV_REDIS_PORT` 再运行 `pnpm setup:dev`。已有 `.env` 时同时修改 Compose 端口和对应连接串，然后重建开发容器。不要改动别的项目数据库。

### 后台 403 或登录后操作失败

使用 `http://localhost:5173/admin/`，核对 `ADMIN_ORIGIN`，重新登录。不要关闭 CSRF 或 Origin 校验。

### 图片没有出现在前台

确认图片来自媒体库，内容已经发布，工作台任务为「已同步」，`MEDIA_ROOT` 目录可写。保存草稿不会自动覆盖公开内容。

### Windows 下 Prisma generate 报 DLL 占用

先停止此项目 API，再运行 `pnpm db:generate`，完成后重启 API。不要结束其他项目的 Node 进程。

### Node / pnpm 版本或锁文件不匹配

按 README 指定版本安装，保留 `pnpm-lock.yaml`，重新执行 `pnpm install --frozen-lockfile`。不要用删除锁文件掩盖依赖差异。

### 页面正常但发布任务失败

检查 `WEB_INTERNAL_URL` 是否能从 API 访问到前台，`REVALIDATE_SECRET` 是否相同。确认前台已启动，然后在工作台重试失败任务。
